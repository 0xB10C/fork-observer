How the past states are reconstructed

The activity log records changes, not snapshots. The state shown here is the current state of the nodes with every loaded event undone, one at a time, back to the position on the slider. That is exact for what the events describe, with two gaps: getchaintips results that silently drop a fork tip produce no event, so such a tip stays visible for longer than it should; and a reorg onto a branch the node already knew as a fork tip drops that tip instead of restoring its earlier status.

data.json only carries the blocks the backend still finds interesting, and the tree draws each run it dropped as a "N blocks hidden" link. Those runs are straight lines of blocks, one per height, so a block an event names — the event carries its hash and its height — is put back at the position its height gives it inside the run. Such blocks are drawn flat and greyed, because only their hash and height are known, and clicking them shows no header. Blocks the events can't place, such as a fork tip whose branch point no event mentions, are still missing; the event line above says so when it refers to one.
